Design Principles
01
Hebrew-first, RTL always
כל טקסט, כפתור, ותווית — עברית. ממשק ה-RTL אינו תרגום. הוא ברירת המחדל. אנגלית רק לערכים טכניים (°C, bar, kW/h).
02
Drag is the primary verb
גרירה היא הפעולה הראשית. לחיצה היא קיצור דרך. אין טפסים לפני שרכיב נמצא על הבד. הבנייה מתחילה בגרירה.
03
Never block the canvas
שגיאות לא חוסמות. לא מופיעים דיאלוגים מודאליים. כל שגיאה מוצגת בפאנל הימני בלבד. הבד תמיד זמין.
04
Color = medium
כתום = מים חמים. כחול = מים קרים. ירוק-כחול = סירקולציה. הצבע הוא שפת הצינורות — כל נקודת חיבור, כל קו.
05
One mode at a time
ניטור ובנייה לא מעורבבים. המעבר הוא מפורש — לחיצה על הכרטיסייה. כל מצב מאפס בחירה.
06
Every action is undoable
כל מוטציה בגרף — הנחה, מחיקה, חיבור, שינוי שם, העברה — ניתנת לביטול. מחסנית 50 פעולות. Ctrl+Z תמיד.
Screen Anatomy — Three Zones
Zone A — Library Panel (right in RTL)
24 רכיבים ב-9 קטגוריות. חיפוש בזמן אמת. כרטיסיות קטגוריה עם אמוג'י. כל כרטיס תמיד ב-DOM, display:none כשמוסתר. גרירה עם ghost מותאם. רוחב 300px.
Zone B — Canvas (center)
רשת קווים 32px. Snap ל-20px בגרירה. Zoom: Ctrl+גלגלת, min 0.3× max 2×. Pan: גרירה על רקע. fitView: Ctrl+0. תמיד רוחב חיובי — לא קורס.
Zone C — Properties Panel (left in RTL)
3 מצבים: ריק (✦), רכיב נבחר (hero+פורטים+כפתורים), צינור נבחר (From→Medium→To). רוחב 280px. לא חוסם בשגיאות.

User Journeys — Four Real Paths Through the Product
How to read this
Each journey is the actual current path, step by step — system response under each action — with the friction (⚠) or success (✓) that a real user hits at that moment. These are not aspirational flows; they describe the product as built today.
J1 · MONITORAn operator checks whether the building is OK
Persona: facility operator · Goal: "Is everything running? Anything I need to act on?" · Frequency: many times/day
01 · OPEN
Opens the app in Monitor mode
Header + demo strip + status bar + KPI bar stack above the canvas; equipment grid on the side; live nodes animate.
Four horizontal strips before the canvas; the demo strip nags on every reload (state not persisted).
02 · SCAN
Looks for the building's overall status
"הכל תקין" / alarm count in the header; per-node temps/states on the canvas.
Status answer is scattered across 5 places — no single "is my building OK?" summary.
03 · SPOT
Notices a node pulsing red
Critical node pulses + glows; alarm badge shows a count; alarm banner appears in sidebar.
Alarm color (red) and "hot pipe" color language overlap on the same canvas — momentary ambiguity.
04 · DRILL
Clicks the node
Right inspector opens with values, alarms, sensor state.
Inspector shows telemetry, not "what happened / what to do." Operator must interpret raw numbers.
J2 · BUILDAn installer builds a plant room from zero
Persona: commissioning installer · Goal: model the physical plant room · Frequency: once per project (high stakes)
01 · SWITCH
Finds and clicks "בנייה"
10px segmented toggle in the header flips mode; palette replaces the equipment grid; canvas shows a warm empty invitation.
The mode switch — a fundamental context change — is a tiny header control with near-zero affordance.
02 · PLACE
Drags a component to the canvas
Neon ghost pill follows cursor; canvas glows; on drop a full SVG node appears, auto-named "Heat Pump 1".
Ghost (pill) ≠ result (node). Auto-name uses the English engineering label inside a Hebrew-first UI.
03 · CONNECT
Wires two components
Drags handle→handle; medium inferred from source port; edge drawn, or a red toast if invalid.
No pre-drop compatibility hint — you only learn it was invalid after releasing.
04 · NAME
Renames a component meaningfully
Selects node → opens inspector → expands "פרטים נוספים" → types → confirms.
Rename is buried under an expander that re-collapses on every new selection. Renaming N nodes = N cycles.
05 · SAVE
Tries to save the finished plant
— nothing —
There is no save / export / load. A refresh destroys the entire design. This breaks the core promise of a builder.
J3 · EDITAn engineer corrects an existing design
Persona: commissioning engineer · Goal: fix a mistake in a built model · Frequency: ongoing during commissioning
01 · FIND
Locates the wrong component
Visually scans the canvas; pans/zooms with the controls.
No search / jump-to-component. In a large plant this is pure visual hunting.
02 · DELETE
Presses Delete on a connected node
Deletion is blocked because it still has pipes; the keyboard path swallows the error silently.
Dead end: nothing happens, no message. No "delete this and its pipes?" choice.
03 · UNDO
Makes a mistake, reaches for Ctrl+Z
— nothing — (only Ctrl+D / duplicate is wired)
Undo is promised in the principles & keyboard reference but is NOT implemented. Mis-edits are permanent.
04 · REDO LAYOUT
Drags nodes to tidy the layout
Manual positions persist; ELK auto-layout also runs.
Auto-layout and manual placement compete; the recent "canvas collapses to 0 width" bug shows the pipeline is fragile.
J4 · PRESENTShowing the twin to a client
Persona: sales / project lead · Goal: a clean full-screen view for a stakeholder · Frequency: occasional, high visibility
01 · ENTER
Clicks ▶ or presses F
Header, strips, and both sidebars collapse; only the animated canvas remains; a "presentation" badge shows.
The F shortcut is undiscoverable; no on-screen hint that it exists.
02 · SHOW
Walks the client through the live flow
Animated pipes, live values, alarm pulses read well full-screen.
This is the product's strongest moment — but it's display-only.
03 · SHARE
Client asks for a copy
— nothing —
No shareable link, PDF, or report. Presentation mode is the only "output" and it can't leave the screen.
Current Product Critique
Ground rule: brutal honesty
This section judges the product as it is built today, not as the blueprint above describes it. A recurring theme: the blueprint documents a richer, more finished product than the code implements — undo, arrow-key nudge, F2-rename, zone navigation, and 50-step history all appear in the spec but are absent in the build. Each item below cites the specific behavior or file. Severity: Blocker trust-breaking · Major hurts daily use · Minor polish.
Top 20 — UX Weaknesses
01
No persistence at all Blocker
Everything lives in an in-memory GraphStore. A reload erases the whole design. A "builder" you cannot save is a demo, not a tool.
02
Undo is promised but not wired Blocker
Principle 06 and the keyboard reference both claim "Ctrl+Z always / 50-action stack." The only Ctrl handler in MissionControlView is Ctrl+D. Mis-edits are permanent.
03
Documented shortcuts don't exist Major
Arrow-nudge, Shift+nudge, F2-rename, Ctrl+0 fitView appear in the keyboard reference. The real handler only does Esc / Delete / Ctrl+D. The spec oversells the build.
04
Mode switch has no presence Major
Monitor↔Build is a 10px segmented toggle in the header — a fundamental context change with the affordance of a footnote.
05
Two disjoint selection systems Major
Monitor uses local selectedComponentId; Build uses the FSM. Selecting a node in one mode is forgotten on switch — selection never carries across.
06
Two competing ways to place Minor
Click-palette-then-click-canvas and drag-to-canvas both exist, with no guidance on which to use — two mental models for one outcome.
07
Delete fails silently Major
Deleting a connected component is blocked by an empty catch on the keyboard path. The user presses Delete and nothing happens — no message, no reason.
08
Connection form is a 4-dropdown maze Major
Wiring via the panel means four cascading native <select>s buried under "פרטים נוספים" — the slowest possible path, redundant with drag-to-connect.
09
Auto-names are English Minor
New nodes are named from def.label ("Heat Pump 2") inside a Hebrew-first UI that otherwise hides English entirely.
10
No real onboarding Major
Beyond one static empty-canvas hint, there's no first-run arc: no "start here," no sample plant, no guided first connection.
11
Presentation mode is undiscoverable Minor
Entered via the F key or a ▶ button with no hint F exists; Esc exits only when no drawer guard intercepts it.
12
Four strips before the canvas Major
Header + demo strip + system status + KPI bar stack vertically, pushing the actual content — the canvas — down the screen.
13
Inspector width jumps per mode Minor
360px in Monitor, 280px in Build. The canvas reflows every time you toggle modes — a small but constant jolt.
14
Palette search is weak & hidden Minor
Behind a 🔍 toggle; matches only the Hebrew name and raw typeId — no synonyms, no fuzzy, no English fallback.
15
Category labels are truncated Minor
heLabel.split(' ')[0] shows only the first word: "נקודות צריכה"→"נקודות", "מקורות חום"→"מקורות". Meaning is lost.
16
Drag-only is exclusionary Major
The palette's primary verb is drag. Keyboard users and touch users who can't fine-drag have no obvious add-to-canvas path.
17
No sense of "done" Major
Nothing tells you a design is complete, fully connected, or physically valid. There is no finish state, checklist, or review gate.
18
Three different empty states Minor
Canvas (⬡ hexagon), build inspector (✦), monitor inspector (⬡) each invent their own "nothing here" metaphor and icon.
19

If We Started From Zero Today
Ignore the current implementation entirely. If we designed the Builder from scratch — knowing it must feel like a premium Building Operating System and serve installers, engineers, and operators — here is the shape it would take. The organizing belief: the user models a building's intent; the software generates the schematic.
North Star
Model intent, generate the schematic
Today the user is forced to think like a P&ID drafter: place ports, draw pipes, infer media. Instead the user should declare intent — "a heat pump heats this storage tank," "this tank serves the showers on floors 1–3" — and the system derives the connections, media, and layout. The schematic becomes an output you can inspect, not a chore you draw. Manual override stays available for experts, but it is never the price of entry.
Foundation 01
One model, two lenses
No "Monitor mode" vs "Build mode." There is one building model seen through a Plan lens (configure) or a Live lens (observe), with a single edit affordance — like Figma's view/edit. Selection, zoom, and focus carry seamlessly between them.
Foundation 02
Persistent & versioned from line one
Autosave is non-negotiable. Every change is a step in a named, branchable history — restore yesterday, fork a "what-if" scenario, compare two designs. Infinite undo/redo is the floor, not a feature.
Foundation 03
Start from a template, never blank
First run asks "what kind of building?" and drops in a sensible starter plant you refine. Blank canvas is an expert escape hatch, not the default. Importing a parts list or a standard plant is one action.
Foundation 04
A single design system
Tokens only — zero hex in components. One brand accent, a restrained neutral palette, a defined type scale, a consistent elevation system, and one equipment illustration set used identically in the library, on the canvas, and in the inspector. Motion is reserved for meaning (a pump actually turning), not decoration.
Foundation 05
Connection as a guided act
Hovering a source highlights every compatible target before you commit; incompatible ones dim with a reason. A "complete the circuit" assistant suggests the obvious next link. Deleting a connected component offers "remove with its pipes" — never a silent dead end.
Foundation 06
Design-level health
Beyond runtime alarms, the model continuously validates the design: "this tank has no heat source," "this loop never returns," "no sensor on the hot supply." A quiet readiness score tells you when the build is genuinely complete.
Foundation 07
Three input modes, all complete
Drag, click, and keyboard each fully build a plant. A power user can add-connect-name without the mouse; a touch user on a tablet never needs a precise drag; nothing is exclusive to one input.
Foundation 08
Output is a product
A design produces a shareable link, a PDF, and a commissioning checklist. The work leaves the app and speaks to stakeholders who will never open the editor.
The 60-second first run
What "from zero" feels like
0:00 Welcome — "What are we heating today?" → pick "apartment building, central hot water." 0:10 A starter plant appears, pre-named in Hebrew, already connected and already "live" with demo telemetry. 0:25 A gentle nudge: "Add a solar collector?" — drag once, the system wires it and shows the new flow. 0:40 The home view says "הכול תקין" with a soft green. 0:55 "Share with your team" produces a link. The user has built, connected, validated, and shared a building — and never once thought about a port.
Product Benchmark
Where the desired experience should borrow from the best-in-class — and where each reference is a trap. We currently resemble the one product on this list we should look least like (SCADA). The goal is the warmth of Apple Home with the power of Figma and the rigor of CAD.
Figma
Collaborative design canvas with a real object model, components & variants, and a plugin ecosystem.
StealA single infinite canvas; components → instances (our equipment library should work exactly like this); infinite undo; inline comments; view-vs-edit as one model, not two apps.
AvoidPro-tool density and a thousand panels would overwhelm a facility operator. Borrow the model, not the cockpit.
FigJam
Figma's playful, low-stakes whiteboard — easy connectors, stickers, zero fear of "breaking" anything.
StealFriendly connector UX (drag from edge, snaps, just works); a warm, unintimidating first impression; the feeling that experimenting is safe.
AvoidToo loose and imprecise for safety-critical mechanical config. Keep the friendliness, add rigor.
Miro
Large-scale collaborative boards with templates, frames, and a strong present mode.
StealTemplate-first onboarding; frames as zones/floors; a polished presentation mode (the one thing we already do well).
AvoidBoards become sprawling and slow; infinite freedom turns into clutter. A building plant needs structure, not a mural.
Apple Home
Consumer smart-home control: status at a glance, scenes, rooms, plain language, one accent.
StealThe "is everything OK?" summary; scenes & automations as first-class; rooms as the organizing metaphor; calm single-accent visual language. This is our north star for feel.
AvoidOversimplification hides the pro detail commissioning engineers need. Layer depth under the calm surface — don't remove it.
Home Assistant
Power-user home automation: entity model, dashboards, deep automations, huge community.
StealThe entity + automation model; configurable dashboards; history graphs and trends as a core surface.
AvoidNotoriously complex setup — the cautionary tale. Power must not cost first-run comprehension. This is the trap we must consciously dodge.
SCADA systems
Industrial supervisory control: real-time plant truth, disciplined alarms, P&ID fidelity, redundancy.
StealAlarm discipline (states, debounce, acknowledge), live trends, deterministic state, and never lying about what's real.
AvoidThe 1990s aesthetic and operator-hostile density. This is exactly what we currently look like — borrow the rigor, reject the look.
Professional CAD
Precision engineering tools: constraints, layers, measured drawing, component libraries, snapping.
StealAlignment, snapping & constraints; reusable component libraries; measured precision when it's wanted.
AvoidSteep learning curve and mandatory precision. Keep accuracy optional — assistive, never a gate to getting started.
